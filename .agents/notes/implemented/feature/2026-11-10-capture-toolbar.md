# Agent Note: 精简截图底部工具条

Status: implemented

## Problem

截图入口和工具太多，用户分不清。原来框选后的确认会回放保存的动作链，而这条链默认是贴图，所以普通截图也会留下浮窗；选区工具条只有一排，窄屏会出屏，也只能撤销、不能重做。

## Decision

macOS 14 及以上，自定义选择器框选后显示两排底部工具条：矩形、箭头、文字、马赛克、序号、撤销、重做、识别文字；输出一排是取消、钉在桌面、保存、复制图片，复制图片是主操作。

- **输出意图**：`CaptureSelectionOutput`（`Sources/CaptureCore/CaptureSelectionMarkup.swift`）决定选择器关闭后跑哪些步骤。
  - 交互截图按 Enter 或主按钮，只复制。
  - 正常完成时，只有点「钉在桌面」才创建浮窗。
  - 动作或脚本显式给出的 `after` 优先；脚本截图（带 completion）沿用保存的动作链。
  - 保存的动作链本身和默认值 `[.pin]` 不变。
  - 失败兜底沿用原有规则：自动保存、复制或识别失败时停止后续步骤，并把截图留成浮窗（设置说明「处理失败后停止后续动作，并将截图保留为贴图」）。这是「失败不得丢失截图」的保障，用户在 2026-11-10 的审查后确认把它作为「只有点钉在桌面才创建浮窗」的例外；代价是启用自动保存且写入失败时，这次不会复制。
- **标注历史**：`CaptureSelectionMarkup` 只存标记，不存冻结的整屏画面；新标注会清空重做记录。预览和导出共用 `CaptureDocument.draw`。
- **保存**：
  - 设置了快速保存目录，就直接写入；否则弹出 NSSavePanel。
  - 取消，或失败并提示后，回到选择器，截图和标注都不丢。
- **识别文字**：卡片里的文字可以改，「复制文字并结束」复制的是改过的文字。返回截图时保留标注；无结果或失败时保留重试和返回。
- **布局**：`CaptureSelectionGeometry.toolbarLayout` 按组换行，`toolbarOrigin` 规则是：放在选区下方，下方放不下就移到上方，再放不下就放进选区内侧，并且始终夹在屏幕内。
- **命名**：截图输出的动作叫「钉在桌面」；贴图管理（分组、历史、锁定等）仍用「贴图」，保持输出动作与管理对象的区分。
- **入口**：
  - 菜单只留截图、钉贴剪贴板、打开图片、录屏。
  - 长截图、文字/LaTeX 贴图、动作、贴图组等收进「更多截图工具」。
  - 设置中，自动保存和动作链收进截图保存设置的「高级」，动作脚本编辑器收进动作设置的「高级」；保存位置和快捷键留在基础设置。

## Alternatives considered

- **沿用保存的动作链作为 Enter 的行为，只把默认值改成复制** —— 好处是改动最小。没选，是因为它会改写已有用户保存的配置和脚本语义，规格明确不允许。
- **选择器标注复用 `CaptureDocument` 的撤销历史** —— 好处是语义现成。没选，是因为它每一步都要快照整张图片，在选择器里拿全屏冻结画面做历史太重。
- **左侧工具栏或分步布局** —— 用户在原型阶段已选底部布局，因为它更贴近选区，也能直接复制。

## Consequences

- **收益**：普通截图正常完成时不再在背后生成浮窗。动作链与脚本接口不变。长截图、贴图组等能力仍在，只是不在主界面。
- **代价与已知上限**：
  - 选择器标注只有红色、固定线宽，复杂编辑仍要走编辑窗口。
  - macOS 14 以下仍是系统选择器，不显示这套工具条。
  - 用户若反馈「Enter 应该跑动作链」，或要求选择器内调颜色，需要重访这个决定。

## Verification

- CaptureCore 测试：`CaptureSelectionMarkupTests`（历史、序号、渲染、输出意图）和 `CaptureSelectionGeometryTests`（换行、上移、夹紧）。
- ThermoApp 测试：`CaptureSaveModelTests.testSelectorOutputsCopyWithoutPinningAndCopyReviewedText`（输出不额外贴图、复制改过的文字）。
- 首次落地时，本机只有 CommandLineTools：ThermoApp 测试和实机交互都没能运行，CaptureCore 用替代运行器执行，175 项通过；这不能代替标准 XCTest 和应用集成验证。
- 本地交付边界为静态检查；迁移到最新上游后，13 个改动 Swift 文件语法解析通过。完整构建、标准测试和实机交互由上游验收，未执行项不视为通过。
