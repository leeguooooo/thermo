# 浏览器工作流 Skill 试测

场景由 [近期调用抽样](../../docs/measurements/workflow-discovery-2026-10-17.json)主动发现，没有要求用户提供题目。两个任务分别模拟延迟完成和动作已提交但回复丢失。模型必须实际调用本地夹具，最终输出由回执和操作日志核对；只写出预期答案不能通过。

这里执行的是离线、有状态的浏览器形状夹具，不是真实 Chrome 或业务 MCP。之前的真实 Chrome 验证用于核实场景；不能把这轮离线模型结果称为生产页面验收。候选 Skill 只在临时项目中使用，不安装到用户目录。

```sh
# 无模型请求的回归，模拟每条命令重新起算 monotonic 时钟
python3 scripts/test-browser-workflow-eval.py

# 显式启动四个隔离 Codex 会话；目录必须不存在，不重试
python3 scripts/collect-browser-workflow-eval.py /tmp/thermo-browser-workflow-new-run
```

固定模型 gpt-6.1-sol、medium、Codex CLI 0.163.0，两组各两项任务，同时启动。双方均收到相同工具说明和目标；候选组额外显式读取 Skill，会多一次往返。模型只有临时项目写权限，任务禁止读取实现、状态、场景和日志。事件审阅需核对是否遵守此限制，不能仅依靠夹具日志评分。私有 Home 中的认证副本在对应进程终止后删除；原始事件和 stderr 不整体归档。

通过条件包括最终 JSON、只提交一次、实际读取 Saved 回执、夹具未修改和操作有效。请求原生输入、缓存输入、输出分别保留；不把缓存与输入相加，也不把请求总量当成 Skill 正文大小。耗时包含模型往返和夹具等待，不能当浏览器性能。

第一轮夹具 v1 使用跨命令持久化的 monotonic 截止时间。在模型执行环境中，写入的截止时间约 2.21，但宿主同名时钟约 82,568；后续命令反复看到 Saving，即使 expect 已返回 Saved。这是夹具失效，四条结果全部保留为无效实验，不作为 Skill 通过率。v2 使用 epoch 截止时间，单条命令内部仍用 monotonic 控制等待，并持久化最终 Saved 状态，避免后续读取回退。修正后先验证独立沙箱命令和重复回执，再开始新的四次模型运行；没有更改 Skill 或原始结果。

## v2 实际结果

[审阅页](../../docs/measurements/browser-workflow-live-2026-10-17/review.html)展示输出和逐项验收；[计量与限制](../../docs/measurements/browser-workflow-live-2026-10-17/manifest.json)、[操作与评分](../../docs/measurements/browser-workflow-live-2026-10-17/details.json)、[Thermo 配对结果](../../docs/measurements/browser-workflow-live-2026-10-17/comparison.json)可复核。冻结文件与 [v1 无效实验](../../docs/measurements/browser-workflow-live-2026-10-17/invalid-v1.json)一并保留。八次运行均已结束，认证副本均已删除。

| 观察 | 带候选 Skill | 基线 |
|---|---:|---:|
| 整项任务通过 | 2 / 2 | 2 / 2 |

候选减基线的两个配对差值中位数：原生输入 +26,992.5 token，输出 +58.5 token，经过时间约 +3.22 秒。缓存输入分别记录，没有与输入相加。候选在回复丢失后先读回执，再等待和读取最终回执；基线直接等待后读取最终回执，两者都没有重放点击。显式 Skill 读取使候选每题额外增加一次模型 / 工具往返。

逐条命令已核对：仅执行提供的夹具操作和候选组的 Skill 读取，没有读取实现、场景、状态或事件文件，也没有修改夹具。三项无模型回归通过，其中跨进程时钟起点测试能重现 v1 问题，并验证 v2 的终态不回退。

这两个任务没有区分出成功率收益，现有记录也没有显示操作数减少，因此不安装或默认注入这个新候选。不能把两次配对推成所有 Skill 都无用，也不能据此判定现有 chrome-use Skill 不好。后续应发现工具知识不足、复杂表单或恢复分支等实际失误，再验证针对这些问题的指导；不要继续重复已两组通过的相同任务来制造收益结论。
