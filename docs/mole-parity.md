# Thermo 与 Mole 的对齐验收

先补可靠性与核心流程，再打磨界面。参照对象为本地 Mole 原生 App 1.16.0（324），函数证据见 [Mole 研究](mole-native-functions.md)。各项必须分别验证，不能用一轮修复代表整体齐平。

| 项目 | Thermo 当前证据 | 待验收 |
|---|---|---|
| 卸载预览与执行一致 | `AppUninstaller.plan` 捕获路径身份和应用关键文件信息；执行拒绝已变化的应用，逐项跳过替换后的残留；旧计划要求重新预览。卸载测试 17 项及 CleanKit 测试 314 项通过 | 清单到预览之间的应用身份变化；真实应用预览后更新场景 |
| 清理保护与恢复 | 已有运行状态、白名单、Trash 批次和恢复身份检查 | 按清理入口核对保护一致性、部分失败和恢复结果 |
| 扫描取消与超时 | 取消令牌已改为线程作用域，显式传递到磁盘、项目和应用数据扫描子任务，避免并行扫描串扰；应用体积测量限制为最多 4 个任务，取消后不再发布部分结果。新增 3 项隔离测试通过 | 阻塞系统调用取消后是否继续占用工作线程；连续重扫的资源上限 |
| 窗口生命周期 | 关闭时移除 HostingController，释放页面树；停止浏览器检查、应用体积测量、空间概览、文件分析、重复文件扫描、内存与计算采样。恢复时重建页面，保留导航及共享模型；内存采样丢弃退役后的迟到结果。AppKit 控制器释放、位置保留及 SwiftUI 消失/恢复测试通过 | 逐页核对后台任务和 RSS；共享模型仍保留结果数据 |
| 风扇退出保护 | Thermo 明确约定 helper 独立持有策略，CLI/App 退出后继续生效；helper 启动与退出调用自动恢复，不能照搬 Mole 的 App 退出语义 | helper 自动恢复失败和断连的故障注入；验证硬件状态与提示一致 |
| 软件管理 | 已有卸载和残留数据入口；新增用户 LaunchAgent 列表、启用/停用、确认、读回复核、历史与撤销入口，CLI 支持 JSON 和预览。新增 Homebrew 应用检查、单项更新和版本复核；自身已更新而安装记录陈旧的应用不再列为待安装。启动项与更新分别标出 `userLaunchAgents` / `homebrewCasks` 覆盖范围 | Sparkle、Electron、网站等其他更新渠道；系统服务和 App 登录项目前通过系统设置管理；原生安装包结构、签名、架构与回滚仍需独立验收 |
| 磁盘分析与优化 | 已有空间、内存、隐私及开发工具清理模块 | 对照主要操作逐项验收；区分估计大小与实际回收空间 |
| 界面与交互 | 暂未完成同场景对比 | 扫描、审阅、执行、失败恢复和空状态的真实界面验收 |
