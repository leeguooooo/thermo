# 文字与图片翻译

取景器菜单的“翻译设置…”配置服务；图像和文字贴图的“翻译…”打开翻译窗口。菜单也可载入剪贴板文字。打开窗口和本机 OCR 不发送网络请求；点击“翻译”，或明确调用翻译脚本/CLI 动作，才发送文字。

默认关闭翻译。先选择服务、填写语言代码及凭据，再应用。支持有道批量文本翻译、百度通用文本翻译，以及返回 Chat Completions 格式的兼容接口。兼容接口需填写完整 URL 和模型 ID；默认地址只是一个模板，不会自动选择模型、创建账号或发起验证请求。

APP ID 与密钥保存在钥匙串，设置数据不含凭据。凭据与服务及完整 API 地址绑定，改地址后不会把原密钥发往新地址。空白密钥表示保留此地址已有的凭据；更改 APP ID 需要同时填写对应密钥。“忘记此地址的翻译凭据”只操作当前表单地址，删除当前启用地址的凭据时也会停用翻译。保存设置失败会尝试恢复原凭据。

通常原文语言为 `auto`，目标为 `zh`、`en` 或 `ja`；完整语言代码以服务商为准，有道的 `zh` 映射为 `zh-CHS`。窗口中的“本次译文语言”仅影响这次窗口，不改全局默认值。

图片先由本机 Vision 识别文字，当前图片的标注和遮挡会先合并到识别用副本，不读取标注前的隐藏像素。两种输出为：

- 译文文本：可编辑原文和译文，复制或创建普通文字贴图。原生文字贴图可只翻译选中的文字，未选择时使用全文。
- 覆盖回图片：按 OCR 区域翻译，每项可手工修正，再创建一张独立图像贴图。当前使用白底覆盖和自适应字号；放不下的文字会报错，不能静默截断。原图和原标注不被替换。

覆盖模式不包含智能背景修复、复杂表格/竖排重排或服务商原始图片翻译 API。与 PixPin 的服务端图片接口不同，本实现仅上传识别后的文字，不上传图片像素。复杂背景、密集小字、旋转文字和更多语种仍需继续验收。

文字输入上限为 64000 个 UTF-8 字节，最多 256 个区域。客户端分批处理并保持区域顺序；服务返回数量不符、原文对应不符、空结果或模型输出不完整时会拒绝该结果。百度按换行分段，有道按重复 q 参数批量发送；兼容模型需按请求要求返回顺序一致的 JSON 字符串数组。长文本分批不会自动重试失败批次。

只允许 HTTPS，或数字回环地址的本机 HTTP 接口；不接受 URL 用户名、密码、查询参数或 fragment。请求使用临时会话，不带浏览器 cookies、不使用 URL 缓存或默认 HTTP 凭据库，也不跟随重定向。响应上限为 1 MiB，全部译文上限为 256000 字节。分批之间保留间隔，百度/有道连续调用也保留间隔；没有应用层自动重试。服务错误显示状态或错误码，不展示可能包含原文/凭据的原始响应。

取消、修改原文或切换输出模式会使旧请求结果失效。已经被服务接收的请求不能回滚；取消后不会继续后续批次或创建译文贴图。设置改变只取消窗口的翻译工作，不丢弃仍在进行的本机 OCR；新的服务设置用于之后的发送。CLI 请求可通过对应请求 ID 取消。

## 脚本与 CLI

先在应用中配置并启用服务。脚本动作返回译文字符串，不自动复制或创建贴图：

```js
return thermo.perform('translateClipboard');
```

```js
if (thermo.perform('screenshot')) {
  return thermo.perform('translatePin');
}
```

`translatePin` 使用当前图像贴图的本机 OCR，或当前文字贴图的选中文本/全文。文件、颜色和公式类型不通过这个入口翻译。脚本使用保存的默认目标语言；返回值仍受脚本通道的大小上限约束，长译文可使用窗口输出。

```sh
thermo capture action translateClipboard --json
thermo capture action translatePin --json
thermo capture action translationSettings --json
```

GUI 中同名翻译动作打开审阅窗口；脚本和 CLI 调用则明确向已启用、已保存凭据的服务发送文字并等待真实结果。没有配置时会报错，不自动改用其他服务。

协议依据：[PixPin 功能及两种模式](https://pixpin.cn/docs/other/translate)、[PixPin 服务配置](https://pixpin.cn/docs/configuration/translate-key)、[有道批量 v3 API](https://ai.youdao.com/DOCSIRMA/html/trans/api/plwbfy/index.html)、[百度签名及分段规则](https://api.fanyi.baidu.com/doc_bd/21)、[Chat Completions](https://developers.openai.com/api/reference/resources/chat)。有道签名的长文本截取采用官方 Python3 示例的 Unicode 码点规则。真实厂商账号、计费、额度、更多字符和语种的兼容性尚未验收。
