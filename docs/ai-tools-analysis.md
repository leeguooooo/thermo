# AI 工具分析

[当前验收范围与剩余缺口](ai-tools-acceptance.md)按原始问题列出能力、证据和不能推断的结论；下文保留实现与历史验证细节。

thermo 的 AI 工具页需要回答：配置是否有故障、定义有多大、实际调用是否顺畅，以及 MCP / Skill 是否帮助完成任务。这四项需要不同证据。

当前已实现静态占用、显式连接检查、日志观察和本地任务对照导入。可以比较工具定义 / 返回文本大小，定位连接失败阶段、描述或 schema 问题、Skill 空正文和本地引用问题；不能根据长度或一次握手自动给出整体质量分。

App 与 CLI 的调用列表增加了 MCP / Skill 各分类返回文本的合计和 token 占比，分母包含未展开的行。参考计数缺失或编码不一致时，token 合计和占比保持未知，不使用已知部分凑出百分比；字节合计可独立保留。缺失日志、缺失结果和非文本内容仍不在合计内，请求计数另列。真实调用中的条件断言失败也说明：明确错误标记不能直接等同于服务故障。界面和 CLI 补充了这一说明，解析器保留原始标记，不从任意正文猜测错误类别。[源码验证与限制](measurements/tool-usage-return-shares-2026-10-17.json)包含 31 项测试、21 行仅显示 20 行的 CLI 验证和中文离屏图；这项改动尚未进入 393 包。

[完整 App 的隔离验证](measurements/tool-usage-native-qa-2026-10-17.json)使用自有合成日志：MCP 21 项共 84 字节、21 token，每项 4.8%；Skills 1 项独立显示 8 字节、2 token、100%。展开到全部条目不会改变分母；切换参考编码会先提示旧报告，重新分析后更新计数并重置展示行数。验证中发现配置说明仍称实际用量未测量，现已改为分别说明“连接并检查”和“分析本地日志”的作用。3 项本地化测试和修正后的完整窗口检查通过，QA 进程已退出。这是当前源码的 arm64 Debug 验证，不是正式安装包或业务任务质量验收。

[本机静态盘点](measurements/ai-tools-current-inventory-2026-10-17.json)在当前支持的本地配置范围内发现 36 条 MCP 配置、29 条启用，来自 Claude、Codex、Gemini 和 Cursor。Codex 范围有 138 个独立目录 / 插件 Skill 文件，cl100k_base 普通文本参考计数为目录描述 16,581、完整文件 413,671 token；两者分开计量，缓存 215 个文件另列。876 次本地引用检查发现 2 个当前缺失的目标。以上不证明实际加载状态，缺失目标也可能需要在运行时生成。未逐项连接真实配置，因此本机 MCP 定义完整总量仍未知。

## 已实现的静态 Skill 检查

`thermo agents context [--agent AGENT] [--root PROJECT] [--json]` 只读取配置与 Skill 文件，不启动 MCP，不执行工具，不读取会话正文。按完整 SKILL.md 的估算 token 排名，输出目录描述、正文和完整文档的独立测量。App 的 Skills 分类按宿主汇总占用，显示最大的五个独立文件；逐项清单保留所有来源。可在 App 选择 Skill 项目，或回到用户范围。

- 字节、字符和行数来自原始文本，输出不包含正文。
- token 是 `ascii4-unicode1-v1` 启发式估算：每四个 ASCII 标量计一个 token，每个其他 Unicode 标量计一个 token。它不代表任何模型的分词结果或账单。
- 目录项由 name 和完整 description 构成，完整文档含 front matter。两者不能相加当作实际加载量。未读取引用文件。
- 递归检查独立 Skill，找到 SKILL.md 后不继续把其 scripts / references 当作独立 Skill。包含 Codex 的 `.system` 目录。
- 每个文件最多读取 1 MiB，扫描最多处理 10,000 个目录节点、深度 16。无法读取、循环链接或达到上限会报告不完整；统计只覆盖成功读取的文件。
- 使用设备号与 inode 识别文件，符号链接、硬链接和重复来源只计一次文档占用；无法取得文件身份时回退到规范路径。相同正文但独立存储的文件不合并。文件身份仅输出哈希。
- 文档按文件去重，目录描述按文件与插件命名空间去重。同名但不同文件只提示来源重叠，不推断宿主只会保留一个。若扫描期间同一身份出现不同内容，相关文件从总量排除。
- Codex 插件缓存按 marketplace / plugin / version 盘点，支持 portable、Codex 和 Claude 兼容清单。缓存版本可能过期、关闭或由桌面端管理；本地 enabled 只作为配置证据保留，不当成当前加载状态。所有缓存版本单独统计，不混入目录与已配置 Claude 插件的总量。普通扫描不执行 codex plugin list。
- 项目范围只在显式传入目录后读取：从所选目录向上至 Git 根标记的 `.agents/skills` 和 `.claude/skills`。没有 Git 根标记时只查所选目录，不扫描无关父目录；不递归搜整台机器的仓库。项目目录选择后会清掉旧范围报告，再扫描；进行中的检查和修复不接受范围变更。
- 嵌套、项目和 Codex 缓存条目不提供删除操作，避免沿合集链接移除共享目标。

汇总是静态清单，不是最终会话上下文；目录描述和完整文档也不能相加当实际消耗。JSON 的 summaries 区分条目数、成功测量数、独立文件数、重复文件条目、目录估算、文档估算、缓存数量和变化 / 身份未知的排除项。按 --agent 过滤会同时保留对应共享来源与覆盖警告。

仍未覆盖管理员目录、宿主通过远程服务提供的 Skill、会话内动态加入的目录、宿主配置的完整优先级与启用覆盖规则。工作树主检出回退规则也未模拟。因此不能把静态目录总量称为“该宿主当前加载的全部 Skill”。

发现规则参考 [Codex Skill 位置与同名行为](https://developers.openai.com/codex/skills)、[Codex 插件缓存布局](https://developers.openai.com/plugins/build/plugins)、[Claude Code 项目 Skill 与同名规则](https://code.claude.com/docs/en/skills)。这些规则于 2026-10-17 核对；实现对未识别的加载状态保持未知。

## 本地参考分词

`context`、`inspect`、`usage` 可增加 `--encoding cl100k_base` 或 `--encoding o200k_base`；默认 heuristic 保持旧的低成本估算。App 的 MCP / Skills 分类可选择同样的编码。它们是普通文本参考编码，不自动映射模型名称，也不宣称等于 Claude、最新模型、工具包装、图片或账单用量。

- 使用 OpenAI tiktoken 0.14.0 的词表和普通文本预分词规则，保留所有格与正则量词。BPE 用最小堆与相邻片段合并，按 rank、再按左侧位置选取；不实现解码器或自动下载接口。
- 编译进二进制的两份压缩词表约 2.9 MiB 源码，运行时不依赖 Python、资源目录或网络。原始词表 SHA-256、转换后二进制哈希和规则记录在 Resources/TokenVocabularyProvenance.json，加载时验证转换数据哈希。
- NSRegularExpression 使用系统 ICU；referenceEngine 标识本地实现、参考版本与 ordinary 模式。测试验证的是当前主机上与官方参考的符合性，不是所有系统版本和任意模型的实际上下文保证。
- 老字段 estimatedTokens / estimator 保留启发式结果，新增 referenceEncoding、referenceTokens、referenceError。参考值不可用时保持 nil / 错误代码，不把启发式结果伪装成参考计数。对比排序将不可用项放到末尾；有缺失文件的参考汇总保持未知。
- 单次文本上限 1 MiB、单个预分词片段上限 65,536 字节。触及边界返回 input_limit / piece_limit。控制标记按普通文字处理，不当作隐含的模型控制 token。
- 日志的参考计数只用于返回文本，请求原生 token 记录不变；非文本结果仍保持未知。MCP 将列表读取与本地定义分析分开计时，单项连接检查也不再为发现服务而重复统计全部 Skill。

[本轮对照与打包证据](measurements/reference-tokenizer-2026-10-17.json)记录了 488 项相关回归、独立 CLI 和旧报告回读结果。Debug 包复制到无资源目录后仍能计数；root helper 未带入词表符号。未公证或安装验收。

Tests/AgentDoctorTests/Fixtures 保留由官方 tiktoken 0.14.0 生成的 734 个 token ID 样例，包含语言、schema、组合字符、emoji、NUL、空白、重复文本和随机 Unicode 标量；独立 CLI 夹具另外验证文档、目录、MCP schema 和日志返回值。开发者可用 scripts/generate-tokenizer-reference.py 重建样例，scripts/generate-token-vocabularies.py 使用固定哈希的官方表重建内嵌数据；这些脚本不是产品运行依赖。

## Skill 内容证据

每份成功读取的 Skill 增加 quality 元数据。解析由固定版本的 [Swift Markdown 0.9.0](https://github.com/swiftlang/swift-markdown/tree/0.9.0) / cmark-gfm 完成，依赖提交记录在 Package.resolved 中。检查不执行 Skill、脚本或 MCP，不联网获取引用，也不读取引用文件正文。

- 检查 Markdown 链接、图片和已解析的参考式链接，保留原 SKILL.md 行号。代码块、行内代码、HTML 注释和未解析成链接的括号文字不会当作文件引用。
- 只核实静态相对路径。URL、绝对路径、锚点、变量和 glob 不查；编码空格和嵌套括号按 Markdown 解析，父目录引用从真实的 Skill 文件位置解析，避免链接目录改变 ../ 的含义。
- 目标不存在与无权限 / 无法核实分开处理。缺失引用明确写“当前不存在”，提醒判断它应随 Skill 打包还是使用时生成，不宣称 Skill 一定不能用。
- 去掉元信息和注释后没有正文会列出 empty_body；没有长度评分，也不把长文档直接判为差。
- 同一宿主下、独立文件的 SKILL.md 完全相同会给 info 提示和来源，别名 / 硬链接不算独立副本。缓存的多版本不参与重复安装提示；缓存引用问题只作信息证据，不当成已加载版本的健康故障。
- 每份文档最多处理 100,000 个语法节点、512 个引用；取消或达到上限明确标为检查未完成。HTML href、引用锚点正确性和任务语义不在检查范围。

App 显示内容检查数量，问题详情给出来源及行号；信息条目也可展开证据。旧报告没有 quality 时显示尚未采集，不能用 0 个问题代替未知。

内容汇总现在按宿主区分目录 / 已配置插件与缓存，以文件身份去重别名；独立存储的相同正文仍分别计数。缺少文件身份、未测量、缺少内容证据及观察不一致各自单列；同一文件的正文或引用检查结果不一致时，不任选一次计入合计。部分检查保留已取得的引用和发现数量，并明确列出检查不完整。逐项来源和问题记录仍保留，不因汇总去重而删除。

`agents context --json` 新增可选 `qualitySummaries`；CLI 按 `--agent` 过滤后重新计算。旧报告没有该字段时仍可读取。缓存仅表示本地存在的文件，不证明它已启用或加载；这些静态发现也不构成 Skill 效果评分。历史盘点中的逐条检查数没有改写，不能把去重后的下降当成修复数量。


本轮验证的是文档可用性，未连接 Unity、执行建模或运行 Unity 测试；不推断 Skill 的业务成功率收益，也没有修改或向上游提交同步器代码。

## MCP 主动检查

App 的 MCP 页保留本窗口内手动“连接并检查”的计量，显示已完整检查 / 启用配置数、未完成、进行中和停用数量，以及已检查部分的工具数、定义字节、各定义数组计数之和、独立服务指令计数之和、定义提示数量与跨配置前十名工具。未检查或未完成的配置不按零计；存在缺项时仍明确显示完整配置总量未知。普通扫描不会为了填满汇总而连接服务。

这份汇总按配置 ID 保留最新一次检查，同名服务在不同宿主或来源中分开计量，不合并成一个会话。数字是独立文本计数之和，不是重新序列化为一个提示词的分词结果，也不是宿主实际加载量。排名只包含计数可用的工具，不可计数的数量另列。为控制内存，每条配置只为汇总保留最大的十个工具计量，不保留定义正文；单项结果仍展示完整工具列表。

重新检查开始时立即移除该项旧成功计量；失败、超时或取消不会沿用旧值。重新扫描、切换编码 / 项目或开始修复会清空汇总，旧操作迟到的结果不能重新写入。清除计量只清空内存，不改配置，不关闭用户自己的服务；当前不持久化历史。

“选择 MCP 配置并检查…”提供批量入口。默认没有勾选项，打开面板不会连接服务；可按宿主筛选，切换宿主会清空选择。只有点击“检查所选配置”才按列表顺序串行连接，停用项不参与。单项时限可选 10 / 30 / 60 / 120 秒，总检查预算为 120 秒，收尾可能稍晚结束。失败保留原因并继续下一项，不自动重试；停止、关闭面板或离开页面会取消当前检查，不再启动后续配置。未开始项单独计数，不按成功或零占用处理。

批次开始时移除所选配置的旧计量，包括尚在队列中的项；取消后不会出现旧成功数据。检查结束、当前连接收尾前，配置扫描、修复和编码切换保持禁用；独立检查尚未结束时也不能开始批次。清除或重新扫描会同时移除过期批次进度，迟到结果不能恢复旧数据。最近一次批次的结果与当前待检查的选择分开显示；这仍是配置计量，不证明宿主正在加载所选服务。

[批量检查验收](measurements/mcp-batch-inspection-2026-10-17.json)记录了 274 项 App / 本地化检查及隔离原生窗口操作：默认未选择、成功结果明细、切换宿主清空选择、取消首项后保留两项未开始、重查不沿用旧成功计量和清除过期进度。期间修复了选择项与结果项标识冲突导致结果行隐藏的问题。总预算和串行性由可控时钟 / 执行器夹具验证，原生操作只连接本地合成服务；没有启动真实配置清单中的 29 个服务。此前 fb0aeee 的双架构验证包不包含本次新增批量界面。

## 本地使用历史

`thermo agents usage [--since ISO_DATE] [--agent claude|codex] [--limit FILES] [--all] [--json]` 显式读取本地会话日志。默认最近 7 天、最多 100 个文件；日期简写 YYYY-MM-DD 按 UTC 解释。App 的 MCP / Skills 分类共享一次“分析本地日志”的结果，支持按返回文本、明确错误、观察耗时或次数排序；项目选择不会改变这块跨项目统计的范围。

- 来源是 `~/.claude/projects` 与 `~/.codex/sessions` 中最近修改的 JSONL 文件，不包含归档目录。只处理窗口内、带有效 ISO 时间戳的记录。按文件修改时间选择意味着保留旧修改时间的导入日志可能不在范围内。
- 最多发现 20,000 个目录条目，递归深度 6；最多读取 64 MiB，每个文件只读末尾 4 MiB，单行最多 1 MiB，扫描阶段最多 20 秒。超限、取消、截断、无法读取、无效 JSON 和缺失关联均在 coverage 或调用条目中保留。读取使用打开文件的长度快照，未结束的末行不作为完整事件。
- 通过宿主、会话与 call id 关联调用和结果，过滤重复记录。调用按开始时间归入窗口；窗口外开始、窗口内结束的不算新调用。支持 Claude 的 tool_use / tool_result、Codex 的 function_call / custom_tool_call 及对应结果。MCP 识别日志中的 mcp__server__tool 名称，以及 Codex 的 event_msg / item_completed / McpToolCall 原生事件。后者使用明确的服务、工具、结果和毫秒起止时间，不解析脚本字符串推断调用；缺少原生事件的脚本嵌套仍无法完整归因。其他工具调用保留数量，不能据此断言其中没有 MCP。
- Skill 目前只识别 Claude 显式 Skill 工具调用。隐式注入、通过普通文件读取加载 Skill，以及 Codex 的 Skill 使用不能完整识别。没有观察到记录不等于没有使用。
- 结果出现算 completed；只有明确布尔 is_error / isError 标记才归为已知错误状态。普通返回文本里的 ERROR 字样不会被猜成失败，缺少状态标记保持未知。结果缺失也不等于失败或成功。
- 耗时是日志调用至结果的时间间隔，包含宿主和传输开销，不代表纯服务执行时间。异常负间隔不计入样本。中位数依有效样本计算，至少 20 个样本才给最近秩 P95；累计间隔可能互相重叠，不能当作实际经过时间。
- 返回文本单独计量，JSON 的 returnedTextEstimator 标识启发式算法版本。标准内容块只统计 text；图片等非文本块计数但不估算 token。结构化输出仅在没有 content 时序列化计量，避免把同一结果重复加总。报告只保留工具 / Skill 名称与聚合数字，不写入提示词、其他参数或返回正文；Skill 名称须通过标识符字符校验。脱敏后同名的工具也用原始名称哈希保持独立。
- 请求 token 单独列出：Claude message.usage 与 Codex token_usage_record.payload.usage。原生 msg_ / resp_ ID 跨镜像日志去重，其他 ID 在会话内去重；渐进计数使用较新的记录。Codex 累积 token_count 不求和。缺失或不支持的记录保留计数，缓存字段缺失保持未知；不同宿主的缓存字段不归一化、不再与 input 相加。

请求 token 不分摊给工具，也不根据调用所在的整条模型消息推算工具占比。这份报告不提供账单、任务成功率或“哪个版本的工具更好”的结论。按照日志名称汇总也不能证明它对应当前安装版本。
